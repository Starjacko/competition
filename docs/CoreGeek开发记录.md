## 3. 本次工作的总体思路

本次完善遵循四个原则：

1. **先保证协议稳定，再增加策略复杂度**  
   无论输入是否完整，服务都要返回包含 `roleCommandMap`、`prompt` 和 `executeCmd` 的响应，避免因异常导致整局中断。

2. **按业务职责拆分代码**  
   战斗、经济、任务和动作校验分别放入独立模块。`brain.py` 只负责识别昼夜、组织执行顺序、处理建筑布局和调用模块。

3. **先生成候选动作，再统一校验**  
   策略函数不直接假设动作一定合法，所有候选动作最后经过 `validator.py` 检查，降低接口字段错误、越界和角色类型错误的风险。

4. **采用可解释的规则策略作为 Demo 基础**  
   当前优先使用确定性规则，便于本地重放、调试和验收。后续再逐步接入跨回合记忆、评分模型和 LLM 任务决策。

## 5. 已修改和新增内容

### 5.1 `brain.py`：从业务堆积改为回合编排

当前职责：

- 解析输入并构造 `Turn`。
- 根据回合号识别白天或黑夜。
- 调用白天和黑夜策略模块。
- 规划武器建造位置和围墙顺序。
- 调用寻路模块为角色生成下一步位置。
- 调用统一校验器，生成最终 `roleCommandMap`。
- 在输入异常时返回协议要求的空响应。

白天大致流程：

```text
基地受压判断
-> 低血量用药
-> 建造缺失武器
-> 建造围墙
-> 采矿或卖矿
-> 开拓者处理任务
```

黑夜大致流程：

```text
识别武器
-> 分配最近且未占用的控制角色
-> 角色移动到武器附近
-> 判断冷却
-> 按威胁评分选择机器人
-> 生成攻击命令
```

### 5.2 `combat.py`：独立夜间战斗策略

已增加：

- 控制角色分配，避免一个角色同时控制多座武器。
- 基于距离和角色 ID 的确定性控制者选择。
- 武器攻击范围判断。
- 机器人目标威胁评分。
- 对 Boss、大型机器人和靠近基地目标提高优先级。
- 根据武器等级限制一次攻击的目标数量。
- 武器冷却期间不重复发起攻击。
- 低血量角色自动使用背包中的 `medicine`。

当前攻击目标排序主要考虑：

```text
机器人类型威胁权重
> 距离基地的接近程度
> 机器人剩余生命值
> 机器人 ID 稳定排序
```

### 5.3 `economy.py`：独立资源和交易策略

已增加：

- 背包已满时前往最近的 `vendor`。
- 到达商店附近后出售可出售矿物。
- 石头低于安全库存时优先采集石头。
- 石头库存满足防线需求后，在铁矿和铜矿中选择价格更高者。
- 采矿目标选择最近资源点。
- 采集目标加入本回合占用集合，减少多个角色抢同一资源点。

当前保留石头安全库存 `2`，用于支持围墙建设。该数值是 Demo 策略参数，后续应根据实际建造消耗和对局统计进行调整。

### 5.4 `tasks.py`：独立开拓者任务流程

已增加：

- 识别有效且冷却结束的任务点。
- 开拓者向任务点移动。
- 到达任务点后接取任务。
- 已有上一轮 LLM 结果时提交答案。
- 没有活动任务时不重复提交。

当前接口只使用请求中已经提供的 `llmResp`，没有在 Agent 内部自行调用外部 LLM。这样可以避免阻塞回合响应，也避免在没有完整上下文时生成不可验证的答案。

### 5.5 `validator.py`：统一动作合法性校验

已增加以下校验：

- 角色是否存活且存在。
- 动作名称是否在协议允许范围内。
- 攻击不能在白天执行。
- 建造和采集只能由 worker 执行。
- 接取任务和提交答案只能由 pioneer 执行。
- 移动目标是否相邻、在地图内、可通行且没有被阻挡。
- 采集目标是否为矿点且在相邻范围内。
- 建造目标是否相邻、为陆地且没有被占用。
- 攻击控制器是否为有效武器。
- 控制角色是否在武器附近。
- 攻击目标是否在武器射程内。
- 攻击目标数量是否符合武器等级限制。
- 使用物品是否确实存在于角色背包。

校验失败的候选动作会被丢弃，不会阻止其他角色继续执行。

### 5.6 `protocol.py`：完善输入状态模型和命令构造

已完善：

- 地图宽高和区域解析。
- 我方角色、敌方角色、机器人和任务字段解析。
- 基地、围墙、武器和资源点的统一查询。
- 2×2 基地占地计算。
- 昼夜回合计算常量。
- 武器等级和攻击范围的默认映射。
- 商店价格和卖出价格字段解析。
- 最近一轮动作结果、宝藏结果、新闻和 LLM 返回值保留。
- `move`、`collect`、`build`、`attack`、`sell`、`use` 等命令构造函数。

## 6. 关键设计说明

### 6.1 昼夜识别

当前使用回合号计算阶段，不依赖外部传入的阶段文本：

```python
phase_round = (round_no - 1) % 130 + 1
is_day = phase_round <= 70
```

即每 130 回合为一天，其中前 70 回合为白天，后 60 回合为黑夜。

### 6.2 寻路

`grid.py` 使用带启发式的网格搜索，允许八方向移动，并考虑：

- 地图边界。
- 非陆地区域。
- 我方单位占用。
- 机器人占用。
- 移动角色自身位置。

策略模块只请求“向目标靠近的一步”，不直接重复实现寻路。

### 6.3 冲突规避

回合内使用 `claimed` 集合记录已经被其他角色预定的位置或资源点，减少：

- 多个角色走向同一个格子。
- 多个角色采集同一个资源点。
- 多个角色同时建设同一个位置。

这属于轻量冲突处理，尚不能替代完整的多角色动作规划。

### 6.4 注释规范

当前注释以解释“为什么” 为主，不对显而易见的赋值语句逐行注释。建议继续遵守：

- 每个策略模块的公开入口使用简短 docstring。
- 复杂的优先级、坐标计算和协议兼容处理添加说明。
- 不在代码中堆积长篇任务书原文。
- 参数发生变化时同步更新策略文档。
- 涉及接口不确定性的地方明确写出假设，便于后续核对。

## 8. 当前已知限制

以下内容目前仍属于待完善功能，不能视为已经完成：

1. 没有持久化的跨回合记忆，服务重启后会丢失策略上下文。
2. 购买、使用、丢弃和升级策略还没有完全根据商店字段闭环。
3. 任务流程只有基础接取和提交，尚未实现完整的 LLM 调用编排。
4. 尚未实现复活、召唤宝藏和宝藏线索的完整策略。
5. 武器控制分配没有综合角色健康、路径风险和武器重要程度。
6. 基地受压判断使用固定距离阈值，尚未结合机器人攻击范围和移动趋势。
7. 没有完整的角色间动作优先级仲裁器。
8. 缺少结构化日志、指标统计和失败回放工具。
9. 缺少单元测试、协议契约测试和完整 HTTP 集成测试。
10. 当前策略参数仍是人工经验值，尚未通过对局数据调优。

## 9. 后续优化路线

### 阶段一：协议和测试加固

目标是让每个动作和每个异常分支都可重复验证。

- 增加 `tests/` 目录。
- 为 `protocol.py` 增加最小字段、缺失字段和错误类型测试。
- 为 `validator.py` 增加每种动作的合法与非法样例。
- 为昼夜边界、基地 2×2 占地和八方向寻路增加回归测试。
- 增加本地 HTTP POST 集成测试。
- 清理测试请求中的固定 ID 假设。

### 阶段二：策略状态和资源闭环

目标是让白天经济行为服务于夜间防守，而不是单纯采矿。

- 增加轻量 `memory.py`。
- 记录每日矿价、角色分工、建筑计划和上一回合动作结果。
- 根据武器、围墙和药品的缺口动态调整资源优先级。
- 完成购买、升级、使用和出售的库存闭环。
- 为矿点、商店和建筑点增加不可达后的备用目标。

### 阶段三：战斗和防线优化

目标是降低夜间基地受损和控制角色无效移动。

- 按机器人类型、血量、距离基地和预计伤害建立统一威胁分数。
- 结合武器射程、冷却、等级和目标重叠进行火力分配。
- 为武器控制角色增加备用分配方案。
- 将围墙缺口、基地入口和武器覆盖范围纳入布局评分。
- 增加夜间移动风险判断，避免角色穿过机器人附近。

### 阶段四：任务、新闻和宝藏

目标是把外部信息转化为可执行目标。

- 解析官方消息和民间传闻中的有效线索。
- 维护任务生命周期：发现、接取、执行、提交、完成、失效。
- 记录 LLM 调用次数和每日额度。
- 对 LLM 输出做格式、长度和安全校验。
- 完善宝藏召唤、线索追踪和结果回写。

### 阶段五：对局模拟和参数调优

目标是用数据替代单纯经验参数。

- 建立多回合请求回放器。
- 记录每回合输入、候选动作、最终动作和接口结果。
- 统计资源收益、基地受损、武器命中、角色死亡和任务完成率。
- 对石头安全库存、基地压力阈值和目标权重进行参数搜索。
- 增加长局压力测试和异常输入测试。

## 10. 建议的下一步实现顺序

建议按以下顺序继续开发：

1. 先补充单元测试和 HTTP 集成测试。
2. 再实现跨回合 `memory.py`，保存最少必要状态。
3. 接着完成商店购买、升级和药品使用闭环。
4. 然后优化武器分配、基地压力判断和围墙布局。
5. 最后接入任务、新闻、宝藏和 LLM 调用限制。
6. 使用长局回放结果调优固定参数。

这样可以先控制协议和动作合法性风险，再逐步提高策略复杂度。
