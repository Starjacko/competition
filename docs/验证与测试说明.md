# 验证与测试说明

## 1. 项目验证环境

本项目是公司内部举行的编程大赛项目。

代码能否在比赛环境中正常运行，需要提交到公司内部服务器验证。比赛测试时，本程序还要和另一名员工编写的参赛程序进行真实对局。

因此，本地电脑无法独立完成最终比赛验证，也不能只靠本地运行结果判断策略是否有效。

## 2. 本地可以做的检查

本地可以检查以下内容：

- Python 语法是否正确；
- 模块能否正常导入；
- HTTP 请求和响应格式是否符合接口文档；
- 动作指令的字段和值是否正确；
- 单个函数或局部决策逻辑是否符合预期；
- 程序是否能按约定启动并监听端口；
- 使用固定的样例输入时，程序是否能返回结果；
- 静态检查、构建检查和其他不需要真实对手的检查。

本地检查通过，只能说明代码的某一部分工作正常，不能说明完整比赛策略一定有效。

## 3. 本地不能完成的验证

由于无法在本地控制另一名员工编写的参赛程序，本地不能确认：

- 和真实对手对局时是否能够获胜；
- 对手采取不同策略时，本程序是否能够应对；
- 真实比赛中的采集、建造、攻击和防守策略是否有效；
- 公司服务器上的判题器是否接受全部行为；
- 程序在完整比赛时是否会出现超时、异常或资源问题；
- 最终比赛排名和胜负结果。

## 4. 公司服务器必须验证的内容

以下内容必须在公司内部服务器上完成：

- 服务器能否正确启动本程序；
- 判题器能否通过 HTTP 访问本程序；
- 程序能否完成真实对局；
- 本程序和另一名员工的程序对局时是否出现异常；
- 真实对局中的胜负、得分、错误和服务器日志。

## 5. 验证状态的写法

| 状态 | 含义 |
|---|---|
| 本地检查通过 | 语法、导入、接口格式或局部逻辑检查通过；不代表比赛通过 |
| 待服务器验证 | 本地检查已经完成，但还没有公司服务器结果 |
| 服务器运行通过 | 服务器能够启动并运行程序；不代表策略一定获胜 |
| 已完成服务器对局验证 | 已经和真实对手完成对局，并记录了结果和证据 |
| 比赛策略已验证 | 已按照项目要求完成真实对局，且结果满足已经确认的验收标准 |

没有服务器真实对局结果时，不得把功能写成“比赛已通过”或“策略已完成”。

## 6. 真实对局记录

每次公司服务器验证后，应补充一行记录。对手信息可以使用比赛编号或匿名名称，不要复制对方代码。

| 日期 | 代码版本 | 服务器/比赛编号 | 对手标识 | 结果 | 错误/日志 | 后续动作 |
|---|---|---|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 待填写 | 待验证 | 待填写 | 待填写 |

- 在获得服务器提交方式、启动要求、日志获取方式和比赛结果后，应更新本文件并补充真实对局记录。
